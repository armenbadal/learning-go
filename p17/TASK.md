# Խնդիր 3․ Task Events — իրադարձությունների հոսք

Ավելի բարդ

Նպատակ՝ սովորել gRPC streaming-ը և ամրապնդել concurrency-ի գիտելիքները։

Շարունակիր երկրորդ խնդրի `Task Manager` ծառայությունը։ Երբ առաջադրանք է ստեղծվում, ավարտվում կամ ջնջվում, ծառայությունը պետք է այդ իրադարձության մասին տեղեկացնի բաժանորդագրված հաճախորդներին։

Օրինակ՝ հաճախորդը կանչում է `WatchTaskEvents` մեթոդը, և սերվերը նրան հերթով ուղարկում է իրադարձությունները՝ առանց ամեն անգամ նոր հարցում պահանջելու։

### Պահանջներ

1. Սահմանիր `TaskEvent` հաղորդագրությունը՝
   - իրադարձության տեսակը,
   - առաջադրանքի ID-ն,
   - իրադարձության ժամանակը։
2. Սահմանիր `WatchTaskEvents` մեթոդը որպես server-streaming RPC։
3. Երբ որևէ առաջադրանք փոխվում է, սերվերն ուղարկում է համապատասխան իրադարձությունը բոլոր բաժանորդներին։
4. Հաճախորդը շարունակաբար կարդում է հոսքը և տպում իրադարձությունները։
5. Երբ հաճախորդը դադարեցնում է աշխատանքը, սերվերը պետք է դադարեցնի այդ հաճախորդի համար տվյալների ուղարկումը։
6. Իրադարձությունների տարածումը պետք է լինի thread-safe։

### Ի՞նչ պետք է սովորես

- Ինչով է streaming RPC-ն տարբերվում սովորական RPC-ից։
- Ինչպես է աշխատում `stream.Send()`-ը։
- Ինչպես է `context.Context`-ը դադարեցնում երկարատև հարցումը։
- Ինչպես կառավարել բաժանորդներին, ալիքները և goroutine-ները։
- Ինչպես խուսափել data race-ից, goroutine leak-ից և deadlock-ից։

Ընդլայնման առաջադրանք․ ավելացրու bidirectional streaming, որի դեպքում հաճախորդն ու սերվերը կարող են նույն կապով տվյալներ ուղարկել միմյանց՝ անկախ ժամանակացույցով։
